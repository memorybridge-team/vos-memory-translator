### 2. GPU 서버 사용

- 공유 GPU instance의 접속 및 Jupyter/terminal 사용 방법을 확인했다.
- 작업 파일은 서버의 workspace에서 관리한다.
- instance는 실행 중 비용이 발생하므로 사용 후 반드시 정지한다. 삭제에 해당하는 close 동작은 사용하지 않도록 주의한다.
- 초기에는 instance 하나를 공유하고, 동시 사용 충돌이나 수요가 확인되면 추가 instance를 검토한다.
- 다중 접속 시 파일 충돌 가능성과 실제 과금 규모는 추가 확인이 필요하다.

### 3. 현재 연구 진행 상황

- SAM 2에서 frame별 memory가 어떻게 저장되고 tensor가 어떻게 변하는지 확인하는 코드와 분석을 진행 중이다.
- translator 구현 전에 SAM 2의 memory attention과 실제 state 흐름을 충분히 이해하는 것이 우선이라는 데 의견이 모였다.
- source model의 최종 output 전체를 target input으로 단순 연결하는 방식 외에, 중간 layer나 일부 state만 연결하는 지점을 찾는 아이디어가 논의됐다.
- 다만 중간 연결 지점 탐색은 후속 과제로 두고, 먼저 가장 단순한 output-to-input/state-to-state handoff를 성공시키기로 했다.
- 네 checkpoint의 모든 방향을 한꺼번에 다루면 ordered pair가 12개가 되므로, 처음부터 전부 구현하지 않고 한 모델 pair/전환을 먼저 성공시키는 것이 현실적이라는 의견이 채택됐다. 양방향 검증은 이후 목표로 유지한다.

### 4. benchmark와 baseline

- benchmark와 baseline의 개념을 구분했다. benchmark는 평가 dataset/protocol, baseline은 제안한 translator와 비교할 handoff 방법이다.
- DAVIS는 빠른 개발·debugging 용도로 사용하고, 최종 평가는 긴 영상에 초점을 둔 LVOS v2와 hard condition에 초점을 둔 MOSEv2를 중심 후보로 삼기로 했다.
- 회의에서는 SAM 2 학습 데이터와 DAVIS가 겹칠 수 있다는 우려가 제기됐다. 이 내용은 공식 자료로 재확인하기 전까지 `미검증`이다.
- baseline은 target model 자체가 아니라 model switch/handoff 방법을 비교하는 것으로 정리했다. Target Reset 등 현재 설계 문서에 적힌 방법부터 조사하기로 했다.

### 5. translator 학습 및 구조

- 동일한 video prefix를 source와 target에 각각 처리시켜, target-native state를 translator의 teacher/정답으로 사용하는 paired-state 학습 방식을 적용하는 방향을 재확인했다.
- Cross-Model KV Cache Transfer의 교훈을 SAM 2에 적용해 Linear와 Nonlinear translator를 모두 검토한다.
- 회의에서는 model 규모 차이가 작으면 Linear, 크면 Nonlinear가 유리할 수 있다는 가설이 제시됐다. 이는 LLM 결과를 VOS에 옮긴 `가설`이며 실제 SAM 2 실험으로 검증해야 한다.
- positional information은 source 표현에 결합된 상태로 그대로 전달하지 않고, target 방식으로 다시 생성·결합하는 방향을 논의했다.
- positional encoding을 제거해야 하는 정확한 이유에 대해 참석자 사이 해석 차이가 있었으므로, 공식 코드와 논문을 기준으로 다시 확인하기로 했다.

## 결정사항

1. 첫 구현은 모든 model pair를 동시에 다루지 않고 한 controlled pair/전환에서 end-to-end handoff를 먼저 성공시킨다.
2. 단순 state-to-state handoff를 우선하고, 최적 중간 연결 지점 탐색은 후속 과제로 둔다.
3. DAVIS는 개발·debugging 용도로, LVOS v2와 MOSEv2는 최종 평가의 주요 후보로 사용한다.
4. paired source/target state를 수집해 target-native state를 teacher로 쓰는 학습 방향을 유지한다.
5. Linear와 Nonlinear translator를 나누어 탐색하되, 규모 차이에 따른 적합성은 가설로 두고 실험으로 판단한다.
6. baseline은 model 종류가 아니라 handoff 방식으로 정의하고, 기존 설계에 포함된 비교군부터 조사한다.
7. 공유 GPU는 우선 instance 하나를 사용하고, 사용 후 반드시 정지한다. 추가 instance는 실제 수요가 생길 때 검토한다.
8. 다음 고정 회의 시간과 core time은 전체 시간표가 확정된 뒤 정한다. 다음 회의는 주말을 우선 후보로 두되 `미확정`이다.
